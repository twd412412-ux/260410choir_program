# 찬양의밤 리허설 출석

## 사용

- 홈 행사 프로그램에서 `큐시트` 왼쪽의 권한자용 `리허설 출첵` 버튼으로 진입. 공개 자리배치도에서도 진입 가능.
- 관리자도 전체 파트 출석 체크 가능. 파트장은 기존 담당 파트만 수정.
- 가장 최근 지난 리허설을 기본 선택. 휴대폰은 전체 높이를 사용하고 저장 버튼을 하단에 고정. `자리표`/`명단` 전환 시 체크 내용 공유.
- 최초 관리자는 `관리자 날짜·배치도 설정`에서 공개된 **전체 배치도**를 선택하고 설정 저장.
- 기본 날짜: 2026-09-20, 2026-10-04, 2026-10-11, 2026-10-12, 2026-10-16. 9/27 제외.
- 단원 기준, 기존 좌석의 지그재그·센터·행 간격을 기준으로 표시.
- 자리 탭은 출석 체크/체크 취소. `미체크 결석`은 선택한 파트 필터(담당 범위)의 미체크를 확인 후 일괄 결석 처리. 이름 검색어는 적용 범위를 좁히지 않음.
- `출석 저장`으로 서버 반영. 조회 실패 재시도, 저장 실패 입력 보존, 날짜 전환/닫기 시 미저장 확인.
- 저장 실패 시 `최신 불러오기 (내 체크 유지)`: 서버 최신 기록을 다시 읽고 미저장 체크를 다시 적용. 배치도·담당 범위에서 빠진 단원은 반영하지 않고 인원을 알림.
- 출석률 = 출석 ÷ 체크한 날(출석+결석). 지정 날짜 중 한국시간 오늘까지의 회차만 사용하고, 아직 체크하지 않은 회차는 `미체크`로 따로 표시하며 출석률을 낮추지 않음(2026-10-03 사용자 결정).
- `리허설 출석 현황`(2026-10-03 사용자 결정):
  - `파트별 회차`: 회차마다 파트별 출석/대상, 아무도 체크하지 않은 회차는 `미체크`, 일부만 체크하면 `미체크 n`, 파트 출석률(출석÷체크).
  - `단원별 참석표`: 날짜별 ✓ 출석 · ✗ 결석 · · 미체크 · – 대상 아님. 파트 탭(전체/담당 파트). 전체 탭은 파트 묶음을 유지하고 파트 안에서 정렬.
  - 머리글 `단원`·`참석`·`출석률`을 누르면 정렬하고, 같은 머리글을 다시 누르면 방향을 바꿈. 기본은 출석률 낮은순. 체크한 날이 없는 단원은 방향과 관계없이 맨 뒤.
  - `출석률 50% 미만만` 필터. 이름을 누르면 회차별 기록과 저장자·시각을 펼침.
  - 파트 탭·정렬·필터는 기기별로 기억(localStorage `choir_ra_summary_v1`). 서버 추가 조회 없음.
- 관현악 줄과 명부상 관현악 단원은 리허설 대상에서 제외. 합창 줄에 들어간 관현악 자리도 빈칸으로 표시하며 원본 배치도, 기존 출석 기록, 정규 출결은 변경하지 않음.

## 데이터·권한

- 설정: `settings/rehearsalAttendance` (`dates`, `planId`, `version`). 관리자만 설정 가능.
- 기록: `rehearsalAttendance/YYYY-MM-DD`. 정규 `attendance`와 분리되어 주일 결산에 섞이지 않음.
- 관리자가 기준 배치도를 설정한 뒤 화면을 열면 9/20 오후 정규 출결의 출석·지각을 해당 리허설 출석으로 한 번만 반영. 기존 리허설 체크 우선, 출첵 제외·등록 전 단원 제외. 이후 체크 취소를 다시 덮어쓰지 않음.
- 반영 여부/인원은 `afternoonImportedAt`, `afternoonImportedCount`, `importSource`에 기록. 정규 오후 출결 문서는 읽기만 하며 리허설 수정으로 변경하지 않음.
- 기존 `attendanceAdmin` callable의 `rehearsalLoad`, `rehearsalConfigure`, `rehearsalSave` 액션.
- 조회는 `attendance.view` 또는 `attendance.check`; 변경은 `attendance.check` + 기존 담당 파트 scope.
- 신규 출석 권한이나 자리배치 수정 권한을 자동 부여하지 않음.
- 클라이언트가 대상 이름/파트를 지정해 권한을 우회할 수 없음. 서버가 명부의 memberId, 담당 파트, 활성 여부, 출첵 제외, 등록일을 검증.
- 관리자 설정 날짜 외의 저장과 미래 회차 저장 금지.
- memberId 없는 옛 좌석은 임의 이름 매칭 없이 `대상 제외`로 표시.
- 변경한 단원만 트랜잭션 병합. 같은 단원의 상충 수정은 거부, 다른 파트 기록은 보존.
- 저장 중 공개 배치 인원 변경 및 설정 변경 검증. 클라이언트 변경값 그대로 덮어쓰기 금지.
- 날짜 제외 시 기록 삭제 없음. 다시 추가하면 기록 재조회 가능.
- 기준 배치도 변경 후 과거 기록은 보존. 각 저장 문서의 `memberIds`는 당시 대상 목록을 보관.
- 새 컬렉션은 일반 Firestore 직접 읽기/쓰기 허용 규칙이 없음. 모든 접근은 callable 경유.
